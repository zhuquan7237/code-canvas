## 这一版修的是「所有格式都打不开」

你反馈的现象是对的，我上一版的验证漏掉了它：**测试全跑在 debug 包上，而 debug 包不做代码混淆**。

### 根因：发布版的枚举名被混淆了

`DocumentKind` 的常量名（`MARKDOWN`、`CSV`、`PDF`…）是**存进文件的**——文档 JSON 里写着 `"kind":"MARKDOWN"`，读回来时用 `DocumentKind.fromName()` 还原。

发布版会跑 R8 混淆，把枚举常量名改成 `a`、`b`、`c`。于是：

- 存进去的是 `"a"`（或者旧版存的 `"MARKDOWN"` 再也对不上）
- `fromName()` 返回 null
- 每个文件都退化成「未知类型」，按纯文本打开

**这就是「一个都打不开」**：文件其实能进编辑器，但类型全丢了，预览全没了。

修复：`proguard-rules.pro` 里保留 `DocumentKind` 和 `RenderKind` 的枚举名——它们的名字是存储格式，不是可以优化的标识符。

### 第二个原因：首页标签用的是旧的四值枚举

首页的类型标签读的是 `RenderKind`，它只有 HTML / SVG / XML / RAW 四种值（格式扩展之前留下的）。所以 Markdown、JSON、CSV、YAML、图片、PDF 在首页**全显示 `RAW`**。

你看到的「只能打开 SVG 一种」，一半是这个标签造成的错觉。

修复：首页标签改用 `DocumentKind.label()`，十六种类型各自显示正确名称。

### 顺带修掉的

- **清空数据后首页永远空白**：种子标记文件存在但文档为空时不再重新播种，用户清空后看不到任何示例。
- **搜索防抖**：多文件时每次按键都重建整个列表，实测 120 个文件时单次按键 495ms。加 120ms 防抖后降到 **10ms**。
- **`file://` 导入失败无提示**：Android 10+ 禁止按路径读取 `/sdcard`，失败时只弹一个会被界面切换盖掉的 Toast。现在弹明确对话框，并提供「重新选择」直接调起系统文件选择器。
- **测试隔离**：性能测试留下的 120 个文件污染了其他测试（数到 278 个文件）。现在测试自己保证前置状态并验证清理。

## 安装

下载 `code-canvas-0.5.6.apk` 覆盖安装。已有的文件会保留，类型标签会自动恢复正确（`DocumentKind` 会按扩展名重新推断）。

## 已知限制（未变）

- PDF 不支持应用内翻页，提供「用其他应用打开原文件」。
- YAML 只做缩进和括号检查，界面明确标注。
- 从其他应用以 `file://` 路径传文件进来，Android 10+ 不允许按路径读取，应用会引导你用系统文件选择器重新选择。
