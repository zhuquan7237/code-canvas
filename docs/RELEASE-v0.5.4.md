# Code Canvas Android v0.5.4

versionCode 54 · versionName 0.5.4 · minSdk 26

修六项用户报告的缺陷。每一项都定位到根因，并加了会失败的回归测试。

## 1. 大 SVG 依然无法缩放

**两个原因叠在一起。**

预览页里有一段「窗口尺寸变化后重新居中」的逻辑，是我上一版为修图形偏移加的。它把缩放重置回 1.0 —— 手机上任何布局变化（工具栏出现、键盘收起、横竖屏）都会把用户刚做的缩放抹掉。用户看到的现象就是「捏合了，但图没动」。

第二个原因更隐蔽：「适应窗口」对应的变换是恒等变换（1.0 / 0 / 0），而 `pushTransformToWeb` 在遇到恒等变换时提前 `return`，理由是「没变化就不用推」。但恒等变换恰恰是复位指令，跳过它意味着「适应窗口」永远推不回页面 —— 缩放一旦发生就再也回不去。

修复：
- resize 监听保留用户缩放和观察中心，只在未缩放时重新居中
- 恒等变换照常推送

实测（4000×3000 SVG，真机）：
- 双指捏合：页面 transform 1.0 → 1.8
- 放大按钮三次：100% → 274%
- 适应窗口：274% → 100%，图形回到 y=1266..2102（视口 760..2608，完全居中）

## 2. 搜索栏只能输入一个字母

用户报告：输入一个字母就退出输入状态，而且退出的动作会改动 SVG 代码。

补了五条测试覆盖：焦点保持、文档不被改动、计数、无结果提示、关闭后状态。

顺带修掉一个真问题：**关闭搜索时关键词和高亮都残留**。重新打开搜索会看到上次的旧词，高亮也还画在代码上。现在关闭会清空输入框并移除高亮。

实测：输入 `circle` 完整保留，计数 `1 / 1`，文件仍是「已保存」；输入 `zzzzzzz` 显示 `0 / 0`。

## 3. 误输入或删除后无法撤回

**两个原因。**

第一个：撤销历史在离散编辑（粘贴、符号插入、整体替换）时记录的是**编辑后**的文本。撤销时自然就跳过了这一步，直接落到更早的状态 —— 用户感觉「撤销跳得莫名其妙，不知道改了什么」。

修复方式是在 `beforeTextChanged` 里捕获编辑前状态，并保证历史始终以当前文本结尾。

第二个：大文档首次编辑就把历史裁到只剩两条，`canUndo()` 变成 false，撤销按钮点了完全没反应。

实测：输入字符后撤销，字数 725 → 724，重做按钮恢复可用，标题出现未保存标记 `●`。

## 4. 打开代码卡顿

WebView 在 `onCreate` 里无条件初始化并配置。但纯代码文件根本不需要 WebView —— 用户打开 `.py` 只是要看代码。

改为按需初始化（`ensureWebViewReady()`），只在真正要渲染预览时才付这笔开销。

实测：17KB Python 文件打开 1.08 秒，按键延迟 75ms。

## 5. 界面过于紧凑

符号键、搜索栏、视口工具栏都补了间距和最小尺寸。新增 `EditorLayoutSpacingTest`，按平台的 48dp 触摸目标做断言 —— 把「过于紧凑」这个主观判断变成可测量的门槛。

实测：头部按钮 121×121px（48dp）、符号键之间有可见间距、代码区占屏幕 55% 以上。

## 6. 顺带修掉：并发写盘会丢文档

排查测试偶发失败时发现的真实缺陷。Windows 上 `Files.move` 替换目标文件时会偶发 `AccessDeniedException`（目标文件被读句柄占用，常见于杀毒扫描），写盘失败被静默吞掉 —— 文档就消失了。

改为有界重试（12 次，递增等待）。30 轮并发压测全部通过。

## 已知限制（未变）

- PDF 不支持应用内翻页，提供「用其他应用打开原文件」，导出保持原始字节一致。
- YAML 只做缩进和括号检查，界面明确标注「未做完整校验」。
- 自签名 APK 首次安装会被 Play Protect 提示扫描，这是 Android 对非商店来源的正常行为。
