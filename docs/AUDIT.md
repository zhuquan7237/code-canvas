# 代码画布审计（2026-11-12）

代码画布是给 AI 使用者的轻量预览和编辑工具：把聊天里复制出来的 HTML、SVG、Markdown、JSON、CSV、XML 等变成能看、能改、能分享的文件。Android 端是系统 WebView（`com.nous.codecanvas`，minSdk 26）。Windows 当前发布形态是 C# + 系统 WebView2（`desktop/native/`）；`desktop/main.js` 里的 Electron 仍在，但不是当前安装包。

这次按功能、崩溃、边界、未完成功能、数据一致性、错误处理、性能、安全、交互与界面、无障碍、构建与测试逐项核对。下面按优先级列出。状态是本轮处理后的结果。

## 高

| 问题 | 影响 | 状态 |
| --- | --- | --- |
| 编辑器每次保存都新建一条文档记录，丢掉类型、编码、换行、来源地址和二进制标记 | 导入的 GB18030 / CRLF 文件在第一次自动保存后按 UTF-8 / LF 导出；「写回原文件」失去地址；图片打开一次后再预览会丢掉「这是图片」 | 已修复。`updateDocument` 先复制已存储记录，再写入标题和正文 |
| 超过 20 万字符的文件，预览、分享、另存为读的是空编辑框 | 界面写着「预览和分享都正常」，实际交出空白文件 | 已修复。这些路径改读文档里保存的正文 |
| 「保存并离开」在写入完成前就关闭页面 | 刚确认要留下的修改可能还在队列里 | 已修复。离开前等待保存队列 |
| 文件打不开时，分享、另存为、重命名仍可点，且直接使用空文档 | 点这些按钮会崩溃 | 已修复。失败态禁用这些操作并加上空值保护 |
| 目录里的「其它」用 `RenderKind.RAW` 去比 `DocumentKind` 的名字 | Markdown、JSON、CSV、图片全部被筛掉，和「全部」的数量对不上 | 已修复。「其它」表示不是 HTML / SVG / XML 的作品 |
| 图片预览的缩放只改了内部数字，没有作用到图片 | 说明里的「图片可缩放拖动」在界面上没有效果 | 已修复。图片走视图缩放，SVG 仍走矢量变换 |
| 打开图片或 PDF 会触发一次保存，而保存会把空文本写回去 | 和上一条元数据丢失叠在一起，看一眼就把原文件身份冲掉 | 已修复。不可编辑的二进制文件不再走文本保存 |
| 桌面更新清单和 `parseDesktopUpdateManifest` 对不上：仓库里的清单没有 `schemaVersion`，体积字段是 `fileSizeBytes`，备用地址是 `githubUrl` | 页面侧的更新检查解析即失败；测试用的是另一套字段，所以一直是绿的 | 已修复。解析器同时接受新旧字段，清单补上别名，并用仓库里的真实清单做测试 |
| 侧栏 SVG 缩略图去掉 `<script>` 后仍把 `onload`、`foreignObject` 插进主页面 | 恶意 SVG 能在画布页面里执行脚本，而不是被关在预览框里 | 已修复。缩略图会去掉脚本、事件属性和 `foreignObject` |
| 删掉最后一个作品后，编辑区和预览仍留着已删除的内容 | 用户可以继续改一份已经不存在的作品，保存却不会发生 | 已修复。没有选中作品时清空编辑区、预览和标题 |

## 中

| 问题 | 影响 | 状态 |
| --- | --- | --- |
| 保存冲突时，编辑器拿到新修订号后立刻用当前文本再写一遍 | 另一处更新的内容会被盖掉，而且没有提示 | 已修复。内容相同只对齐修订号；内容不同时询问保留哪一版 |
| 从其他应用分享多段代码进来时，只创建第一段 | 其余代码块被丢掉，也没有选择 | 已修复。Android 和桌面都改走「一段一段选」，不拼接 |
| `file://` 导入按显示名在媒体库里取第一条 | 同名的另一个 `report.csv` 可能被打开 | 已修复。路径可读就直接读；多条同名记录对不上大小就拒绝，并提示重新选择 |
| 预览只实现了旧的 `shouldOverrideUrlLoading(String)` | Android 7 及以上的主框架跳转可能留在预览 WebView 里 | 已修复。主框架的 http(s) 交给系统浏览器，`javascript:` 和 `file:` 直接丢弃 |
| 重命名不更新已保存的类型 | `notes.txt` 改成 `art.svg` 仍按文本打开 | 已修复。文本作品按当前文件名重新判断；图片和 PDF 不因改名变成文本 |
| 首页批量分享把所有作品的文本拼在一起 | 图片和 PDF 的正文是空的，批量分享得到空文件 | 已修复。含二进制时按原字节逐个分享 |
| 列表里导出的 MIME 固定为 `text/plain` | 选择器把图片、PDF 也当成纯文本 | 已修复。按作品自己的类型 |
| 外部「打开方式」每次新建一个主页，旋转后还可能再导入一次 | 同一文件出现多份，返回栈里叠着多个主页 | 已修复。主页改为 `singleTask`，并记住已经处理过的地址 |
| 列表绑定在元数据还没准备好时直接抛异常 | 滚动时偶发崩溃 | 已修复。缺元数据时当场补一份 |
| 首页缩略图只用旧的四类 HTML 包装，Markdown / Mermaid 等和编辑器预览不是同一条路径 | 画廊缩略图和打开后的预览不一致 | 已修复。缩略图改用 `PreviewPage` |
| 预览指纹用标题而不是文档 id | 重命名会让缩略图和预览各算各的 | 已修复 |
| 旋转或重建时只等保存队列 1 秒 | 大文件还没写完就开始读旧内容 | 已放宽到 2.5 秒；明确离开时最多等 8 秒 |
| CSV 分隔符只看第一行 | 表头没有分隔符时，下面的制表符文件被当成逗号表 | 已修复。改为看前面最多 20 行 |
| GIF 用 `BitmapFactory` 解码 | 动图停在第一帧 | 已修复。Android 9 及以上用 `ImageDecoder`，更早版本用逐帧播放 |
| XML 解析器若无法关闭 DOCTYPE，失败被吃掉后继续解析；DOCTYPE 扫描还区分大小写 | 防护在异常解析器上会变弱 | 已修复。关不掉 DOCTYPE 就拒绝解析，扫描改为不区分大小写 |
| 应用允许备份 | 作品正文可能进入系统备份 | 已修复。`allowBackup` 改为 false |
| 桌面作品列表不按修改时间排序 | 打开应用后先看到的不一定是最近编辑的 | 已修复。原生宿主和浏览器回退都按时间排序 |
| 桌面原生导入没有 2MB 上限 | 超大文件整段读入内存 | 已修复。超过 2MB 的文件不导入，并说明原因 |
| 更新检查的页面回退路径不产出界面需要的 `status` / `hasUpdate` | 原生检查失败时，页面侧也无法显示更新 | 已修复。增加 `describeDesktopUpdate` |
| 原生更新在提供升级前不要求合法的 SHA-256 和体积 | 坏清单也能弹出「有新版本」 | 已修复 |
| 设置里的「应用内识别剪贴板」没有开关 | 只能改配置文件才能关掉横幅 | 已修复。设置里增加这项 |
| 界面写着 Ctrl+N / Ctrl+O，按键没有接上 | 快捷键没有反应 | 已修复 |
| 格式化遇到 `<script>` 或 CDATA 仍按标签拆行 | 格式化会改坏脚本 | 已修复。这类文档保持原样 |
| 卸载只删快捷方式和注册表 | 安装目录留在本机，用户以为已经卸干净 | 已修复。卸载程序退出后删除安装目录；作品数据目录不动 |
| 生产环境打开了 WebView2 开发者工具 | 正式窗口可以打开调试工具 | 已修复。默认关闭 |
| 页面导航失败也把宿主标成就绪 | 热键可能打到一块空白页上 | 已修复。只有导航成功才接收调用 |
| `systemDark` 被写进偏好文件 | 系统主题变了，文件里还留着上一次的值 | 已修复。保存前去掉这个字段 |
| 桌面测试没有进 CI | 上面的清单错误可以在全绿的情况下合并 | 已修复。CI 增加 `desktop` 任务，运行 `npm test` |
| 主页搜索框、预览按钮、目录里的「设置」对读屏不完整 | 部分操作没有可聚焦的名称 | 已补内容描述，目录「设置」可聚焦 |
| 主题使用了 API 27 才有的 `windowLightNavigationBar`，而最低系统是 API 26 | `lintDebug` 直接失败 | 已修复。这项放到 `values-v27`，Android 8.0 不再引用它 |

## 低 / 本轮未改

这些要么是产品已经写明的边界，要么改下去会变成另一件产品，本轮没有做。

| 问题 | 原因 |
| --- | --- |
| PDF 不能在应用内翻页 | 说明和界面都写了：这一阶段不打包 PDF.js，用其他应用打开原文件 |
| YAML 没有完整语义校验 | 没有 YAML 引擎，界面已标明只做缩进和括号检查 |
| 正则、跨文件搜索、相似度「重复代码」 | README 写明留到后续。编辑器里已有的查找和替换对话框不在这次范围里扩成新搜索产品 |
| Office、压缩包、音视频 | README 写明不在本阶段 |
| Android 更新地址仍信任 GitHub 资源 CDN 的主机名 | 下载会被重定向到这些主机，路径不可预测；安装前仍校验体积、SHA-256、包名、版本和签名。收紧路径会让正常更新失败 |
| 桌面 HTML 预览的 iframe 仍允许脚本访问网络 | Android 预览默认断网。桌面卖点是可交互的实时画布，收成离线 CSP 会让带 CDN 的作品直接空白。缩略图进入主页面的脚本问题已经堵住 |
| WebView2 运行库 DLL 不在仓库里 | 干净克隆不能直接打出 Windows 安装包。这是构建环境，不是应用逻辑；本环境也没有 Windows 编译器 |
| 真机手势、应用内升级的系统安装器最后一步 | 本环境没有 Android 模拟器，也没有 Windows。见文末验证 |
| Electron 开发壳和原生宿主的偏好项不完全一致 | Electron 不是当前发布架构，没有把它重写成另一套宿主 |
| 剪贴板「已处理」标记用的是 `hashCode` | 碰撞才会把下一条横幅吃掉，实际很少见 |

## 构建与测试里原来的缺口

- CI 只跑 Android 单元测试和 debug 包，不跑桌面测试，也不跑仪器测试（仪器测试需要模拟器）。
- 桌面单测夹具和 `docs/update/desktop-latest.json` 不是同一份数据，所以清单坏了测试仍通过。
- Android 的 `versionName` 是 0.5.6，桌面是 0.5.0。两端本来就不要求同号，这次没有为了「看起来对齐」去改版本。
