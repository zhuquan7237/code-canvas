# 代码画布 v0.1.6 发布说明（主页预览图 · 渲染尺寸统一 · 脚本默认开启 · 出现在「打开方式」里）

这一版来自你的四条实测反馈，每条都先找到了根因再改，其中第一条是我上一版自己改坏的。

## 1. 主页为什么没有预览图

**根因有两层，第二层是我上版引入的。**

- 缩略图**只在编辑器里预览渲染完成时才抓**，所以「没打开过的作品」压根没有缩略图，主页只能显示类型封面。
- 更要紧的是：上一版为了修「空白帧被存成缩略图」，我把判空条件写成「画面接近纯白就算空」。而浅色页面的背景色是 `#F8FAFC`（248,250,252）——**正好落进这个条件里**。于是普通浅色 HTML 页面被判定为「什么都没画」，缩略图被丢掉，回退成类型封面。

改法：

- 判空收紧到「**仍然是纯白底**（三通道 ≥252 且极差 ≤4）」，浅色页面背景不再被误伤。
- 新增**主页自动补图**：主页显示出来之后，用屏幕外的 WebView 依次渲染还没有缩略图的作品（一次最多 12 个，离开页面即停，不覆盖已有图）。没用过的作品也会自己长出一张真实预览。

## 2. 为什么有的预览特别小、有的特别大

**根因：HTML 有没有 `viewport` 标签，渲染结果完全不同。** WebView 对没有 viewport 的页面按 980px 虚拟宽度排版再整体缩小，同一段代码就会有时很小、有时铺满；SVG 那边也有类似问题——包装样式只写了 `max-width`，**只能缩不能放**，所以 100px 宽的图形就是个小点，而响应式的会铺满整屏。

改法：给缺 viewport 的 HTML 自动补上 `width=device-width`；SVG 改为按容器宽度缩放（保持比例）。代码生成代码、页面代码变成同一个入口（`PreviewHtml`），编辑器和主页缩略图不再各算各的。

## 3. 预览默认要「允许页面脚本」

**根因：脚本开关默认是关的，而且「只对当前页面生效」，每次打开都要重新点。**

改法：**脚本默认开启**（图表、动画、计算器这类不带脚本就不渲染），开关状态**应用内记住**，随时能关——关掉后仍然真的会拦住脚本（这条专门有测试）。联网还是**按页面单独询问**，保持原来的保守策略。

## 4. 能不能出现在其他应用的「打开方式」里

**根因：清单里虽然有 ACTION_VIEW，但只声明了少量 MIME 类型，而且很多应用（文件管理器、聊天应用）把文件当成 `*/*` 或 `octet-stream` 递过来，所以列表里看不到「代码画布」；分享文件时走的是 `EXTRA_STREAM`，而应用只读了 `EXTRA_TEXT`——文件被直接丢掉。**

改法：加上按扩展名匹配（`.html/.htm/.svg/.xml/.txt`）与 `file://`、`BROWSABLE`，分享支持 `EXTRA_STREAM`（html/svg/xml/octet-stream）。实测在模拟器上：

- 打开 `file://…/demo.html`（octet-stream）→ 候选**只有**「代码画布」；
- 打开 `content://…` + `text/html` → 与 Chrome、HTMLViewer 并列出现；
- 分享 `image/svg+xml` / `text/html` / `octet-stream` → 代码画布出现在分享列表里。

点进来之后直接落在预览页，不用自己再找粘贴入口。

## 验收

- 单元测试 **69 项 0 失败**；模拟器仪器测试 **28 项 0 失败**（含新增：主页为未打开过的作品生成真实缩略图、浅色页面背景不算空白、脚本默认开启 + 关掉后确实拦得住）。
- 模拟器实测：`file://…html` 的候选列表、分享列表、`已是最新 · 0.1.5`（上一版的应用内升级也确认落地：0.1.4 → 0.1.5 → 0.1.6）。
- 截图：`docs/evidence/v0.1.6/`。

## 没做到 / 取舍

1. 主页补图**一次最多 12 个**作品（渲染要占 UI 线程，几十个作品连着渲染会让首页发涩）；超出的部分下次进主页继续。
2. 补图用的是**屏幕外 WebView**，渲染环境和你真机上的预览一致但不完全相同（例如系统字体、深浅色跟随当前主题）。
3. 卡片里的缩略图是**居中裁切**，宽而扁的卡片会显示画面中段；没有做成「顶部对齐截图」。
4. 上一版遗留项（行号栏、文本长度上限统一、搜索移后台、内置证书指纹）本版仍未做。
